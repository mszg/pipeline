# v0.7 — Integrated Excel Evaluation Reporting

This versioned pipeline release adds an automated Excel evaluation report to the
existing long-range Oxford Nanopore workflow. It follows the repository's
annotated `v0.3`–`v0.6` tag format, advancing the minor version to `v0.7`.

Reporting implementation and artifact checks passed against existing KEL and ABO
evidence. This does not establish biological genotype/phase truth or validated
assay acceptance thresholds. Current KEL/ABO QC is **NOT ASSESSED** because the
required minimum target-breadth fraction is unconfigured. No allele/phenotype
interpretation was added.

## Complete pipeline

Inputs are configured directories or individual `.fastq`, `.fastq.gz`, `.fq` or
`.fq.gz` files, a reference FASTA, a sample/amplicon manifest and intended target
coordinates. Input chunks are discovered recursively and staged without changing
the originals. ABO and KEL have been exercised using RefSeqGene `NG_006669.2` and
`NG_007492.3`; other genes require suitable manifest rows, references and target
definitions. This does not assert assay performance for untested genes.

The retained analysis stages are:

1. FASTQ staging, an input manifest and NanoPlot QC, with optional Filtlong filtering.
2. Minimap2 long-read alignment, samtools sorting/indexing and alignment/depth QC.
3. Separate primary, mapped, MAPQ-filtered variant and phasing BAMs; only the
   phasing read set additionally applies its configured length minimum.
4. Merged primer-defined target BEDs, target-aware Clair3 calling, normalization
   and a complete catalogue retaining multiallelic records.
5. Biallelic WhatsHap phasing; a guard requiring exactly one informative phase set
   per target contig before haplotagging, haplotype splitting and coverage QC.
6. Exact haplotype REF/ALT support with ACCEPT/UNRESOLVED decisions, followed by
   reference-guided HP1/HP2 consensus construction with outside-target, low-depth
   and uncertainty masks. The existing supported-deletion mask exemption remains.
7. Amplicon/gene TSV summaries and the new final Excel/JSON evaluation report.

The reporting feature does not change variant calling, filtering, phase guard,
haplotagging, allele support or consensus behavior. The existing indel-support
repair and conservative reconstruction rules remain part of this version.

## Added in v0.7

`evaluation_report` is a strict downstream Snakemake rule and a default target.
It writes `results/reports/pipeline_evaluation.xlsx` and the accompanying
`pipeline_evaluation.json` evidence file. Its five sheets are:

| Sheet | Purpose |
| --- | --- |
| Sample_Summary | Manifest-defined samples/barcodes and expected genes, execution status, overall QC, gene summaries and every explanation |
| Gene_QC | Read counts and denominators, intended-target depth/breadth and coverage gaps, amplicon availability, variants/phasing, support decisions and consensus completeness |
| Variants | Normalized alleles, GT, FILTER, QUAL, DP, ordered multiallelic AD/AF, phased GT/PS and existing support decisions |
| Haplotypes | Informative blocks, phased/unphased heterozygotes, assigned reads, HP depth, FASTA statistics, target masks and sequence-file links |
| Run_Info | Applied configuration/rules, reference coordinates, source paths/hashes, definitions and separate report-code/environment versus available analysis provenance |

Execution and technical QC are separate. Configurable policies assess every
expected gene independently, with separate sample/positive-control/negative-control
criteria and gene overrides. Aggregation is FAIL > NOT ASSESSED > REVIEW > PASS;
all reasons remain visible. Missing required evidence or thresholds prevents PASS.
Zero variants alone is not failure; phasing criteria can be not applicable when
no eligible heterozygotes exist. No opaque numerical score or validated default
gene-wide cutoff is introduced.

The manifest controls identity, including optional display ID, barcode, run ID
and control type. Text identifiers and leading zeros are preserved; repeated
control labels remain separate. Ambiguous pooled identities and incompatible
input provenance cause affected metrics to be withheld. Target coverage uses
the merged intended reference-coordinate union including zeros. Numeric zeros
remain distinct from missing annotations and not-applicable criteria.

The workbook has filterable tables, frozen headers/identifiers, wrapped reasons,
explicit colored statuses and literal external strings rather than formulas.
Long sequences are linked, not embedded. Parsing errors and inconsistent evidence
are explicit; haplotype coverage counts/fractions must be internally consistent.

An explicit `--partial` CLI reads the manifest and available outputs without the
DAG. It retains expected samples and missing genes, labels the report incomplete,
and never infers current execution success from old outputs. A partial report's
overall QC cannot be PASS. The strict rule still fails on missing, malformed or
inconsistent required evidence.

## Running and outputs

Configure local input paths, references, model and private sample metadata first.
For a normal Snakemake installation with appropriate rule environments:

```bash
snakemake --cores 2 --use-conda --dry-run
snakemake --cores 2 --use-conda

# Generate from completed configured outputs; inspect prerequisites first.
snakemake --cores 2 --use-conda evaluation_report --dry-run
snakemake --cores 2 --use-conda evaluation_report --forcerun evaluation_report

# Explicit incomplete report: include every configuration layer in order.
python workflow/scripts/evaluation_report.py --partial \
  --workdir /path/to/run \
  --config config/config.yaml /path/to/local-run.yaml
```

Apple Silicon users should follow the [native setup source bundle](../../deployment/kel-apple-silicon/README.md).
Its historical core/caller locks remain unchanged; the native wrapper requires
the documented additional pinned openpyxl/et-xmlfile install. The dedicated report
environment is declared in `workflow/envs/evaluation_report.yaml`, and the readable
native environment specification now includes openpyxl. These declarations do
not imply a fresh environment solve was tested.

Main outputs include the input/amplicon/gene summary TSVs; normalized and phased
VCFs; haplotagged and HP BAMs; coverage, support and uncertainty TSVs; mask BEDs;
HP1/HP2 FASTAs; and the final XLSX/JSON pair. Full paths, threshold schema,
denominators and native commands are in the [README](../../README.md).

## Source distribution and compatibility

This source release includes reporting code, tests, environment declarations,
configuration, documentation, native setup sources and synthetic fixtures.
Example manifests now use generic labels and input directories; existing runs
must continue to use their original private manifest through a config override.
No analysis thresholds were changed by this cleanup.

Historical generated logs/evidence and sample-result documents were removed from
the new Git tree while retaining local originals and all existing history/tags.
Raw sequencing data, installed environments, credentials, real-sample XLSX/JSON
reports and other generated analysis outputs are not uploaded. The separate
downsampling study and its untracked `Snakefile.downsampling` are not included.
No release assets beyond GitHub's source archives are required.

## Limitations retained

- No interactive desktop Excel/LibreOffice inspection was performed; workbooks
  were reopened and checked programmatically with openpyxl.
- No fresh solve/build of the dedicated reporting Conda environment or the
  updated native environment specification was tested.
- Real multi-sample/control reporting was not tested; these cases used synthetic
  fixtures.
- Unique-molecule counts, HP median depth and original analysis commit provenance
  are unavailable in existing standard artifacts. Missing values are not invented.
- Reconstruction still requires an informative phase block under the existing
  guard. Reporting does not relax it or prove chromosome-wide phase accuracy.
- Technical QC and internal consistency do not establish biological genotype/
  phase truth, clinical validation or validated assay acceptance thresholds.
  This release adds no allele-name or phenotype interpretation.
